# FPGA 图像边缘检测项目交接（2026-10-22）

项目暂停继续调参，冻结当前成果供接手和上板对比。本交接取代 10 月 19 日文档作为当前入口；旧文档及失败记录仍保留作历史证据。最新是**保边中值 v1 A 待上板候选**，不是已经通过实机验收的最终版。

## 1. 当前项目是什么状态

硬件为 Ti60F225 DemoBoard V4 / Ti60F225 I3，SC431HAI 摄像头接 J4，经现有采集、DDR3、图像算法和 HDMI 链路显示。当前工具为 **Efinity 2026.1.132**；最近数字仿真使用 XSim 2025.2。工具安装和有效厂商许可需接手者自行准备，本包不包含个人许可或账号凭据。

当前用户操作是 **KEY3 在五种全屏模式循环切换**：彩色原图 → 灰度 → 中值 → Sobel → 红边叠加 → 彩色。不是早期五分区，也不是旧七模式候选。KEY3 为 A3 / GPIOL_03，低有效、弱上拉、20 ms 消抖；长按只切换一次。用户已确认模式实时、顺序正确、长按行为正确。KEY0 保留复位职责。

HDMI 显示为 1920×1080 / 60 Hz。历史独立 FPS 测量版本测得相机约 12.660 FPS；**不能把显示 60 Hz 当成当前相机 60 FPS，最新 bit 尚未重测采集帧率**。当前算法链路为双像素处理，报告的显示延迟为 6602 个 74.25 MHz 周期。

开发按独立工作副本、设计审批、仿真、Efinity 构建、人工烧录、人工反馈推进。用户现在要求停止继续优化并交接；本次只写文档、校验和打包，不改算法、不重编译、不操作板卡。

## 3. 最新版做了什么，没做什么

在“细化 v1.1”基础上新增 [median9_detail_pair.sv](../_fpga_edge_agent/work/active/track4_v7_median_detail_001_20261022/algorithm/frontend/median9_detail_pair.sv)，调整 frontend 包装、视频配置和工程文件。原 `median9_pair.sv` 及 Sobel、上下文连接、细化模块保持上一版逻辑。

先计算原 3×3 中值，同时检查四组相对方向的窄线证据：同方向两端与中心差不超过 4；其余六点须在中心同一明暗侧、对比至少 16，背景离散范围不超过 8。只对真实内部像素中满足条件的细线恢复中心原灰度，否则保留原中值。默认关闭、停顿、复位、边界与 owner 语义保持兼容，九级共同推进不变。

它希望保住原中值抹掉的窄线、小笔画，让后级获得更多细节；**不保证所有木纹恢复，也不直接解决所有低对比宽边或全部断点**。当前 Sobel T64 / D20 / D18、上下文 gap drop 16、细化 B 的轴向峰值及分叉保护、相机寄存器增益 0x81 / 0x2A 均沿用前版。当前不是完整 Canny，也没有接入历史形状识别库。

## 4. 目前遇到的问题及判断边界

| 现象/问题 | 已有依据 | 当前结论与待确认事项 |
|---|---|---|
| 普通室内光线下弱边漏检，部分边只在强光出现 | 多轮人工反馈，灰度/中值中有些轮廓仍可见 | 不只亮度问题；需要检查后级弱边判定，未宣称解决 |
| 断点、短碎边、细节漏失，仍有杂点 | 细化 v1.1 有改善，但用户仍反馈不足 | 细化与连通、保细节与噪声仍需权衡 |
| 靠近相机后检不出 | 用户对照：彩色/灰度清楚，中值细节消失 | 不能直接归因失焦；保边中值 A 对此提出改进，实机待验 |
| 木纹在中值可见，Sobel 部分没检出 | 三张图确认为灰度、中值、Sobel；有部分补光，约 80–95 cm | 中值之外还存在弱边判定损失；照片非原始像素，不能据此拟合阈值或报准确率 |
| 原质量门槛不能全部满足 | 相关噪声四个案例增加 | 用户接受少量杂点换细节，需实机判断可接受程度 |
| 形式化控制状态与实际工作不一致 | PostgreSQL 未配置，`database/schema.sql` 缺失；旧状态仍 H0 | 沿用已授权本地报告和追加审计；未修改正式 DB/PROJECT_STATE/TASK_LEDGER/APPROVAL_MANIFEST，接手不能仅看旧 H0 认定项目未开发 |

用户希望木纹、细线、外轮廓都尽量保留，不能把所有木纹都当噪声抹掉。三张场景照片在 [incoming 观察目录](../_fpga_edge_agent/observations/incoming/TRACK4-V7-MEDIAN-DETAIL-001-scene-20261022/)，对应 [结构化观察](../_fpga_edge_agent/observations/structured/TRACK4-V7-MEDIAN-DETAIL-001-scene-20261022.json)。照片存在拍屏角度、曝光和摩尔纹，不能等同传感器 RAW/灰度抓帧。

历史 960×540 半屏黑屏、部分重构链路 DDR 异常、早期细化破坏分叉等失败证据保留；不能把旧失败候选当当前推荐版。v5 降阈值及 v5.1 平滑路线预检失败，没有对应已交付 bit。

## 5. 接手后的优化顺序与理想效果

每次只推进一项，交付后停下来由用户验收；不要同时调相机、预处理、阈值和细化，否则无法定位效果来源。

| 顺序 | 具体工作 | 理想效果/验收依据 |
|---|---|---|
| 1 | 同场景、同普通照明、同距离对比细化 v1.1 与保边中值 A；再在灰度清楚的范围逐步靠近；依次检查灰度→中值→Sobel/红边 | 中值保留更多原有细线，边缘/红边对应恢复，少量杂点可接受；五模式实时和长按一次不退化。没有上板结果前不开始下一轮 |
| 2 | 分段定位漏检：灰度有而中值无则处理预处理；中值有而 Sobel 无则单独设计弱边判定 | 确认主要损失环节，用同位置对照和原始像素/可重复样本量化 |
| 3 | 研究局部对比/噪声估计、方向支持、双阈值种子连接等，先模型和合成/真实样本预检 | 普通光照下弱木纹、小笔画更多保留，噪声在用户同意范围；避免盲目全局降阈值。这些是后续方案，当前未实现 |
| 4 | 再研究方向受约束的断点连接与细化/NMS，保护转角、短线、分叉及相邻线分离 | 断点减少、线宽更细，避免跨接无关纹理、抹掉 Y 形分叉或将双线合并；当前并非完整 Canny 滞后连接 |
| 5 | 长时间实机稳定性、当前相机帧率与必要的 Flash 专项验收 | 有可追踪的运行时间/FPS/断电行为证据，再谈最终版本；Flash 需另行人工确认和操作 |

理想目标是在原图/灰度本就可辨认的普通光照与距离内，更完整地保留木纹、细线、外轮廓，同时减少断点并控制杂点。极暗到原图都无细节、超出对焦范围或过曝时，算法不能凭空恢复信息。
