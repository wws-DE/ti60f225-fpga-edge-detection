设每个lane的3×3窗口按行排列为a,b,c / d,e,f / g,h,i，均是中值后的8位灰度。

- 横向三项差为c−a、f−d、i−g；纵向三项差为g−a、h−b、i−c。差值是signed9位，范围−255～255。
- 对每个方向，分别统计三项中≥D的正向支持数和≤−D的负向支持数；每个计数范围0～3，至少2项才支持该符号。零差值不算支持。
- 横向支持必须与Gx的非零符号一致，纵向支持必须与Gy的非零符号一致。主方向定义为绝对值较大的梯度方向；相等时任一方向满足即可。边缘要求主方向具有支持。
- 最终判定：原output_kind允许二值边缘、原L1>64、主方向支持三条件同时满足。不改变梯度计算，不进行乘法增益、截断或饱和。
- 允许在本次批准范围内只比较两个固定候选：T=64/D=16、T=64/D=20。D是支持差的最小灰度跨度。按G节已固定的质量规则选一个交付；不是运行期自动阈值，也不临时搜索任意参数。两者均不满足则报告失败并修订设计，不自动扩展候选。
- 理想垂直阶跃的L1=4Δ：v1阈值96最低Δ25；候选D16最低Δ17，D20最低Δ20。这只是数值灵敏度边界，不能换算成真实识别率提升百分比。
- 图像边缘仍用原复制补边；重复的边界样本也参与支持计数，因此图像最外圈不能套用“独立两行支持”的解释；噪声统计ROI排除外2像素，边界另测契约。

正常样例：沿三行连续的暗背景弱竖轮廓Δ20，Gx=80/Gy=0，三个横向差均20；两个候选均检出，v1因80≤96不检出。正负、横向及对角轮廓应按同一规则处理。

边界样例：Δ16直线阶跃L1=64不检出；Δ17仅D16候选检出；差值等于D计支持，D−1不计；Gx/Gy绝对值相同时采用对称的任一方向规则。纯平坦窗口无边缘。整数Sobel的Gx/Gy奇偶性相同，合法L1总是偶数，因此阈值边界测试用64/66，不制造不可达的65。

噪声反例：单个角样本突变只能在横/纵各一项提供支持，即使原Sobel幅值大也被抑制。局部多像素相关噪声、规则纹理仍可能满足规则，不能承诺全部去除；孤立真实细节或极短线端点也可能被滤掉，须用角点/曲线/细线和实机检查限制这种代价。

失败/恢复：画面错位、停帧、噪点增加、曲线/细线大面积断裂或时序失败均不算通过；保留失败日志、参数和bit身份，由用户加载v1回退。本版不能恢复物理失焦或丢失细节。

## C. 职责、连接与复用

```text
相机/DDR/RGB输入与KEY3控制（复用v1）
  → 原灰度 → 原3×3中值 → 原第二3×3窗口
  --IF1：双lane窗口144bit + valid/ready + 中心坐标/marker-->
MOD1：六级Sobel原梯度通路 + 新方向支持旁路
  --IF2：中心16bit/GxGyL1各22bit/edge2bit + 同一身份-->
原frontend输出槽/状态 → 原桥接结果RAM → 原显示/串行化/HDMI
MOD2：顶层阈值64 --IF3：11bit cfg_threshold→帧/job快照-->
MOD3：编译期启用开关及D（通过桥接→frontend→Sobel参数）
错误仍走原cancel/status/sticky_fault/原图回退，不新增状态机。
```

- MOD1负责R2/R3：只扩展Sobel内部局部支持判定，复用同一窗口，不另造中值/补边/RAM；Gx/Gy/L1原算术和所有输出端口保留。
- MOD2负责R2：在新副本顶层把命名常量96改64，不改内部复位默认256；原首有效帧/job锁存必须继续验证。
- MOD3负责隔离：sobel_pair和frontend_frame_pair增加编译期开关，默认关闭以保持其他实例旧行为；仅本次bridge显式开启，并传最终选定D。不开新运行期端口或控制CDC。
- 新功能启用的frontend仅支持本项目实际连接external_sobel_owner=0；该输入在v1桥接中常量为0。默认关闭的其他frontend/Sobel实例继续支持原共享/外部路径；不声称本版已优化Canny外部拥有者模式。
- 不修改扫描/结果RAM、输出槽、握手图或状态机。两个lane独立算支持并与各自窗口中心同行，edge与中值显示共用原缓存身份。

## E. 局部中文操作草图与不变量

新增状态由Sobel拥有：每lane六个signed9位差；四个0～3支持计数的判定；与流水阶段一致的正/负方向支持位、最终资格位。它们只是当前窗口的在途中间值，没有跨窗口统计、自动调参或历史估计。

1. S1：沿用输入窗口/身份接受边沿；先把8位像素零扩展再按signed9位求六项差，同时原S1角/中间和照旧形成。无效输入只推进气泡。
2. S2：用S1旧差与±D比较，正/负支持各自计数并判断至少2项；布尔求和先扩到2位，避免1位加法截断。原侧和继续登记。
3. S3：原Gx/Gy形成；把对应窗口的正/负支持位再登记到与该梯度相同阶段，不用当拍新差配旧梯度。
4. S4：基于S3旧Gx/Gy确定符号及绝对值主方向，把相符的多数支持合成为每lane资格位；原绝对值和梯度诊断照旧。
5. S5：原L1形成，资格位随同一事务再登记；S6：原L1>T与资格结合生成edge。关闭开关时只采用原比较，中心/Gx/Gy/L1/身份始终走原通路。
6. 每一步都受原pipeline_advance控制；rst/flush/frame_start优先清有效管线。新增数据无需全复位，理由是所有有效输出必须经过完整有效链且资格已被该窗口覆盖；仿真需覆盖冲刷前后和未知值污染。
7. 顶层/bridge/frontend只负责阈值及编译期参数，不复制支持算法。所有资格与edge使用同lane，不通过坐标奇偶交换。

关键不变量：每个有效edge对应一份完整、同配置和同身份的窗口；支持数只计三项；任何关闭开关的有效输出等于v1原Sobel定义；任何冻结周期所有在途资格与梯度同步保持。
