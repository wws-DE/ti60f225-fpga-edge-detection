# 优化v5.1变更卡：先平滑有符号梯度，再恢复弱边和定位峰值

## A. 状态、依据、整体范围与批准对象

任务TRACK4-V7-LOWLIGHT-EDGE-005-REV1；设计版本优化v5.1；日期2026-10-21；阶段READY_FOR_REVIEW；批准状态NOT_APPROVED。继承已批准v5设计B～I中未被本卡明确替换的数值、接口、质量门槛及人工验收规则；v5是一个失败的软件数学实验，不是已实现或已编译的RTL工程。

用户目标仍为“暗处识别不行，边缘不够精细”，其中历史精细问题包括细纹/笔画漏检和锯齿/断续。v5已按批准执行：独立标量和向量模型一致，恢复了弱阶跃，但原噪声±8/16/24每档93744像素中，A误边6270/26232/32246、B为1312/18820/29075，超出v4.1的0/50/2843上限。原和相关噪声均超标，已停止。实际记录见reports/TRACK4-V7-LOWLIGHT-EDGE-005/软件预检结果.md、candidate-quality.json、reference-verification.json；输入、脚本、失败日志均保留。

本卡R1：在原Sobel之后先对有符号Gx/Gy做固定空间平滑，再进行v5的方向/低阈值/峰值/双侧判定，目标是抑制噪声梯度而保留连续弱轮廓。R2：仍输出原中值中心，不让梯度平滑改变已验收前三模式的像素值。R3：通过固定质量/协议/时序门槛后，交付一个bit再等待人工验收。新增空间平滑不能保证保留所有极细纹理，必须测原细线及新增短笔画，不能仅以噪点减少判成功。

代码基线仍为v4.1工作副本的159项输入，清单SHA256 944b77610c16d2269340a917ab2869270089d280c3a68fc720f78e470a00ac4b；v4.1回退bit SHA256 c194210fb0ff0e3f5e81da6746557b36e280fb16c0aa3ec24fa057e5c25ac77f。v5新生成的三个数学检查文件只是参考基线，由该报告precheck-summary.json及failed-precheck-source绑定；未生成三个fine RTL模块，不能当作现成已验证硬件复用。

本轮设计不改变相机增益/曝光、灰度、中值、按键、引脚/时钟/受保护IP，不实现完整Canny或递归滞后，不承诺消除所有锯齿。修改对象为新副本中五个新算法模块、frontend/bridge路由和扫描延迟、XML源表及必要测试/构建/登记。正式DB/PROJECT_STATE/TASK_LEDGER/Approval Manifest不改，继续既有本地报告/追加审计；不联网、安装或自动烧录。

当前关键未知是固定候选能否同时满足灵敏度与噪声/细节指标，以获批后的数学门槛检验；实际画质/板上位流身份尚未独立测得。方案数值、接口、状态、资源预算和失败停止条件已确定，不能把可行性未知记成已通过。

## B. 整体连接、模块与交接

```text
原RGB/灰度/中值/窗口/六级Sobel
  → S1 32bit梯度窗口＋两级平滑
  → [S2同结构，可选] → [S3同结构，可选]
  → v5打包24bit → v5的3×3窗口 → v5峰值/连续弱边判定
  → 原结果槽/八行缓存 → 八行扫描延迟 → HDMI
```

新增signed_gradient_window_pair.sv：适配现有edge_context_window_pair的两行窗口FSM，容器从16扩为32bit，时钟、同步读/延迟写、首尾重放、无同址冲突协议保持，须重新测。每行8个1024×8 EFX_RAM10、两行16块；每个实际平滑级独立拥有自己的RAM/游标/输出槽。

新增signed_gradient_smooth_pair.sv：两级流水计算3×3有符号梯度加权平均，只平滑Gx/Gy，原中心灰度和中心元数据延迟两级原值转发。v5仍需新实现fine_edge_pack_pair/window_pair/filter_pair三个模块，本次覆盖其原批准范围以及本卡接入变化。

新增编译参数FINE_EDGE_SMOOTH_PASSES只支持1/2/3；默认值1，但只有新FINE_EDGE_ENABLE开启时才实例化整条新链。固定候选六组P1A/P1B/P2A/P2B/P3A/P3B，P为平滑次数，A/B的DROP40/32沿用v5，目标H64对应L24/32。不能新增其他次数、阈值、系数或无限搜索。

新分支默认关闭时不实例化/推进平滑和fine链，旧v4.1及external owner逐周期兼容。开启且为算法输出时，原Sobel的ready来自第一平滑窗口，最终fine输出接原frontend结果槽；所有新增级的empty均进入drain。gray_output/external owner仍按原路由；start仅用于当前参与链，取消/flush/换kind或owner隔离全部新级。不得有两个输出源同时驱动或遗留跨job结果。

## C. 局部接口、数值与中文操作草图

IF-S：同一posedge、ready/valid、原11bit x_even/y及sof/eol/eof，每事务两像素；中心16bit、Gx/Gy各22bit（每lane signed11，范围±1020）。输入window每像素32bit：center[7:0]、Gx[18:8]、Gy[29:19]、pad[31:30]=0；pair64bit，两个逐行3×3窗口576bit。存储是位容器，解包后须显式转signed11，不能把负梯度当大正数。

每级平滑核固定为[1,2,1]的外积，权值和16。第一流水级对每行计算Gleft+2*Gcentre+Gright，signed13范围±4080，分别对Gx/Gy及两个lane处理；同时转发原窗口中心灰度/坐标。第二流水级由旧行和计算top+2*middle+bottom，signed15范围±16320；先扩signed16做舍入：非负取(sum+8)除16向下整除，负值取-(((-sum)+8)除16向下整除)。即最近整数、恰半时远离零；输出仍signed11。三次分别舍入，不能偷换为一次7×7滤波并声称完全等价。

在最后一级输出上重新计算M=abs(Gx_smooth)+abs(Gy_smooth)，先扩为11bit再相加，保守上界2040，11bit可表示；禁止复用未平滑的原out_l1。v5的24bit容器仍可完整容纳M，其方向乘积unsigned18和106/256规则保持。低/高阈值、峰平台选侧、方向极性/双侧集合、非递归原始邻居证据及外围edge0均完全沿用v5。

中文操作：各窗口按旧受限游标读RAM、按旧pending延迟写、组合横向三列，在可推进边沿登记窗口；平滑S1仅据当前有效窗口登记行和/中心身份；S2仅据旧S1提交平滑梯度和相同中心；下一平滑级或fine pack只按实际握手接受。无valid推进气泡，停顿时数据/坐标/marker与所有相关状态共同保持。rst/start/flush清在途有效及窗口phase，不全量清RAM；新帧有效状态在历史建立前屏蔽陈旧内容。不允许用新输出回填同一窗口或跨帧平滑。

正常走查：一条弱阶跃沿切向有稳定梯度，平滑后仍有同号梯度峰；经v5双侧弱支持可输出单侧峰位置。平坦高频噪声的正负梯度在固定核中抵消，是否低于阈值由固定噪声输入验证，不预判。反例：真实两三像素短纹与噪声同尺度，平滑可能将其抹掉；原细线/邻线、短笔画与模糊弱几何任一必需门槛失效，都不能交付。M=0即使L=0仍输出edge0。

组合检查：新增级只变梯度数值，原median中心按窗口中心转发，不重新计算亮度；每级仍为两像素/事务且一进一出，原帧/行/列身份不变；原始Gx/Gy诊断及external owner接口不改，只有新路径平滑副本。M从实际平滑梯度重算，避免数值/方向版本错配。更多窗口产生的延迟在D中明确调整，不静默延用6602。

## D. 显示时序、有限缓存与实现预算

显示固定延迟改为8*HTOTAL+2，目标HTOTAL1100时8802个74.25MHz时钟，相对v4.1增加2200周期，约29.63微秒；帧率和每周期两像素吞吐目标保持。不同平滑次数统一用此延迟，不能在运行中变更。

原8192深度不足以存8800周期扫描数据；改为9216×54bit非二次幂循环RAM，写指针/计数14bit。写地址到9215后回0；读地址在write≥DELAY时为write-DELAY，否则为write+(9216-DELAY)，不使用14bit自然回绕代替模9216。DELAY固定8*HTOTAL，必须0<DELAY<9216；目标差距416，读写不碰同址。同步读及原后两级显示寄存器次序不变，固定延迟须实测8802。warm_count达到DELAY前屏蔽输出；大RAM不做复位全清。

原八行结果缓存/13bit地址和完整行frame/row标签保持。最多六个3×3窗口（median、Sobel、三次平滑、fine）都保留中心与EOL重放；设计上八行延迟为结果完整行发布预留行间余量，输出ahead也受窗口未来行需求约束。须在满宽、行尾/帧尾重放和实际顶层测试直接检查每次display读取均命中同帧同完整行；不能只靠“八行大于六个窗口”证明。若行完成来不及或缓存覆盖，停止修订，不放宽row_matches或关闭sticky_fault。

资源预算修改为XLR≤30000、RAM总数≤245、DSP0；三次平滑最多新增48块RAM，fine窗口扩宽新增4块，扫描深度增加的综合分块待实际报告，预计仍在预算内但未验证。原v4.1为22913/175/0。原全部18setup和18hold关系、时钟与约束保持非负，不改时钟/例外达标。扫描模块支持HTOTAL须满足原最小行空白和新8*HTOTAL<9216，W偶数6～1920、H5～1080；本次目标固定1920×1080/HTOTAL1100。

算法仍为同一74.25MHz域posedge接受/更新；不新增CDC/复位域。C++不适用。独立Python参考按矩阵卷积和逐级有符号舍入计算，不模拟RAM/流水；对应契约按job/配置/坐标逐位核对有效交付，取消作废全部在途事务；数值正确不能代替硬件协议。
