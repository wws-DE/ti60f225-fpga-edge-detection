## 交接的核心结论

当前推荐基线已从旧 `track4_board.xml` 自研整机转为 **TRACK4-V7-ALGORITHM-BRIDGE-001**。保留已经能工作的 v7 相机／CSI／DDR／CVO／时钟复位／HDMI 链路，把自研灰度、中值和 Sobel 插入 RGB 显示流；算法未准备好时回退同位置原图，不让算法阻塞基础视频扫描。

## 推荐版的实际效果

五个区域从左至右分别是：彩色原图、灰度、中值滤波、Sobel 二值边缘、彩色图加红色边缘。每区384像素，展示整幅1920×1080图像相应位置的一段；不是五张缩小全图，所以不同区出现不同物体不能当成同一内容的中值定量对照。

灰度公式 `(77R + 150G + 29B + 128) >> 8`；中值为3×3并使用边界复制；Sobel 的 L1 幅值严格大于256为边缘。桥接延迟4402个74.25MHz双像素时钟，约59.29微秒。当前推荐 bit 固定五区、固定阈值，尚不能按键切换。

上游2026-10-18人工记录为“五区都实时变化，边缘位置正常”。这一证据不覆盖中值实机数值等价、当前 bit 帧率、长时间稳定性和全部赛题验收。其后半尺寸版失败并要求回退，本次回退后的现场恢复结果尚未确认。

## 已找到的问题与解决边界

1. **颜色偏紫**：带行奇偶标记的 RAW 支持 BGGR；黑电平16，固定Q8增益R=317、G=256、B=582。用户已经接受颜色，远处白色略偏蓝仍有改进空间。这是特定照明下固定白平衡，不是自动白平衡；早期四个相位候选单独试错并未解决全部颜色问题。
2. **像素顺序**：实际打包／解包链发现每四像素为P2、P3、P0、P1；顶层写入补偿后恢复P0、P1、P2、P3，已进入推荐版。计数正确、颜色看似正常不代表空间顺序正确；这也不证明所有清晰度问题已解决。
3. **帧率认识**：独立FPS版三次快照测到1920×1080、周期约78.98886ms、约12.660FPS。每份63个报文重复携带同一个最近完整帧统计，不能当189个独立帧。HDMI配置1080p60不等于采集60FPS；后续推荐bit没有重新测量。
4. **HDMI格式连线**：历史复核发现未驱动的隐式1位video_format接到2位输入，后续明确绑定RGB格式。修正及局部信息帧测试并不独立证明全部偏色根因；后续色卡／RAW对照才进一步缩小定位。
5. **旧自研无图**：仍需受控比较复位、DDR时钟／参数／约束、启动顺序和采集／发布握手，不能把当前v7路线成功当成旧版根因结案。

## 哪些版本不能混用

| 版本 | 当前结论 |
|---|---|
| ALGORITHM-BRIDGE | 推荐，曾有五区实时和边缘对齐反馈；最后一次从失败版回退后的恢复尚缺确认 |
| ALGORITHM-CONTROL | 候选，仅软件验证；七模式、按键、阈值和字幕仍需专门实机验收 |
| BGGR-WB | 已验证颜色回退，但早于像素顺序修正和算法接入 |
| FPS | 独立输入测量版，约12.66FPS不自动适用于其他bit |
| DISPLAY-HALF | 实物黑屏无信号，撤回推荐；本次Release不提供该失败bit |
| 031/refine | 旧自研调试与根因分析资料，不是当前推荐入口 |

半尺寸失败版将CVO active改为960×540，同时扩大消隐维持2200×1125总周期；还在DDR前抽样RAW。这与标准1080p有效区内居中绘制960×540 RGB不同，总周期相同不足以保证显示器兼容，RAW抽样也有Bayer相位风险。这些是需要验证的复核方向，未被实测证明为唯一黑屏根因。重新实现缩小显示应独立验证，不能继续叠加功能到失败版。

按键候选七模式为GRAY → MEDIAN → DIFF X8 → SOBEL → OVERLAY → SPLIT → COLOR；KEY0保留复位，KEY1/KEY2阈值±32，范围0..2047，KEY3切模式，20ms消抖、长按一次、配置在帧边界生效。DIFF X8是同帧同坐标灰度与中值绝对差乘8并饱和；不是边缘图。该候选没有进入本次推荐Release，不能使用五区版的实机反馈为它签字。
