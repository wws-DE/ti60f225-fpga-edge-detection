# Ti60F225 V4 FPGA 图像边缘检测项目说明

## 1. 项目概述

本项目来自 [ti60f225-fpga-edge-detection](https://github.com/William19-creator-wq/ti60f225-fpga-edge-detection)，面向 Ti60F225 DemoBoard V4 FPGA 开发板，配合 SC431HAI 彩色 MIPI 摄像头、板载 DDR3 和 HDMI 显示链路，实现实时图像采集、边缘检测及后续图像分析。项目同时保存了 RTL 源码、Efinity 工程、仿真与综合证据、板级调试记录、比特流索引和交接文档，适合作为 FPGA 图像处理竞赛的工程基础和调试档案。

- **本地目录**：`桌面\FPGA`
- **上游仓库**：<https://github.com/William19-creator-wq/ti60f225-fpga-edge-detection>
- **当前检出分支**：`main`
- **当前提交**：`73c3ff48`（2026-10-15）
- **项目规模**：约 41,806 个文件、1.0 GB 工作副本；其中包含历史记录、验证产物和工程快照

## 2. 目标功能

项目围绕赛题四的五项基础功能和六项高阶功能展开：

| 类别 | 功能 | 说明 |
|---|---|---|
| 基础功能 | 摄像头采集 | MIPI/CSI 接收、RAW10 数据整理、帧缓存与写入 |
| 基础功能 | 彩色转灰度 | 定点灰度处理并接入视频流水线 |
| 基础功能 | Sobel 与阈值 | 窗口缓存、Sobel 梯度计算和二值化 |
| 基础功能 | HDMI 与分屏 | 视频扫描、输出、叠加及多种显示模式 |
| 基础功能 | 源码与演示 | Efinity 工程、约束、验证记录、比特流索引和演示准备材料 |
| 高阶功能 | 中值滤波 | 3×3 中值滤波，用于抑制噪声 |
| 高阶功能 | 实时阈值 | 按键/寄存器调节阈值并进行消抖与饱和处理 |
| 高阶功能 | DDR 帧存储 | 帧读写、帧冻结和显示链路服务 |
| 高阶功能 | 完整 Canny | 高斯滤波、梯度、非极大值抑制、双阈值和滞后连接 |
| 高阶功能 | 彩色叠加 | 彩色图像与边缘、标注结果的同步合成 |
| 高阶功能 | 形状识别 | 圆/直线拟合、统计、角度投影和候选标注 |

## 3. 主要处理链路

典型视频路径为：

```text
SC431HAI MIPI 摄像头
        ↓
CSI 接收与 RAW10 整理
        ↓
去马赛克/彩色处理、灰度化
        ↓
中值滤波、Sobel 或 Canny 边缘检测
        ↓
DDR3 帧缓存与帧服务
        ↓
彩色叠加、形状候选标注、分屏
        ↓
HDMI 输出
```

各阶段既有独立 RTL/参考模型和仿真记录，也有组合到整机工程中的版本。独立组件通过仿真或综合，不能直接等同于整机在真实摄像头和显示器上的完整验收。

## 5. 当前验证状态

截至 2026 年 10 月 15 日：

- 更换故障摄像头模组后，官方 SC431HAI→HDMI v6/v7 工程可以显示真实画面；v6 偏绿、v7 偏紫，颜色原因仍需定位。
- 自研视频恢复 v1 已完成 Efinity map、interface、布局布线和下载相关构建检查，实物可以稳定显示 HDMI 彩条，但还没有显示真实相机帧。
- DDR 阶段诊断 v1 的实物观察为 D0 闪烁、D1–D5 亮、D6–D7 灭，原始阶段码记录为 `0x1F`。这说明诊断逻辑在运行并能输出彩条，不能单独证明 DDR 校准完成或帧读写正确。
- 灰度、中值、Sobel、Canny、数值拟合、统计和标注等组件已经有不同程度的仿真、综合或软件参考证据；复杂识别的资源闭合和整机效果还没有完成最终验收。

因此，项目目前更适合作为“具备大量组件验证和板级调试证据的开发工程”，尚不能描述为所有基础、高阶功能都已在实物上完成。

## 6. 建议的使用顺序

1. 先阅读 [`docs/CURRENT_STATUS.md`](docs/CURRENT_STATUS.md) 和 [`docs/HANDOFF_2026-10-15.md`](docs/HANDOFF_2026-10-15.md)，了解版本边界和最新硬件现象。
2. 使用 Efinity 打开对应工程 XML。精简整机入口为 `track4_board_refine_from031_20261013/track4_board.xml`；DDR 诊断入口为 `track4_ddr_cal_diag_001_20261015/track4_board.xml`。
3. 使用仓库中的约束、源码和工程配置进行检查；换机器后需要重新确认 Efinity/Questa 路径及必要依赖。
4. 从 [`docs/export/bitstream-paths.csv`](docs/export/bitstream-paths.csv) 查找 Release 比特流，并按 SHA256 校验后再下载到开发板。
5. 实物调试应先确认 DDR 就绪、帧采集启动、帧发布和 `has_frame`，再逐项验证灰度、滤波、边缘、叠加、冻结和识别功能。

## 7. 后续重点

当前首要问题是定位 DDR 原始阶段码 `0x1F`、确认 `cal_done` 和帧发布条件，并恢复自研链路中的真实相机画面。之后需要核对 CSI 帧/行/像素计数、RAW10 解包、Bayer 相位、DDR 数据一致性、HDMI 无撕裂显示和持续处理帧率。复杂识别还需要完成资源优化、任意旋转矩形/圆等目标的完整测试、误检漏检统计以及最终实物演示。
